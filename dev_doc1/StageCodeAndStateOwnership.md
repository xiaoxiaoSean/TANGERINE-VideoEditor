# StageCode 与编辑状态归属

## 统一错误入口

按照 TANGERINE-ZIP 的约定，阶段码固定为五个 ASCII 大写字母和四个数字，例如 `EXPRT0004`。界面显示中文的阶段代码、详细说明、可能原因、建议操作；同一问题切换语言后仍保留原阶段码。

`Tools/StageException.cs` 提供 `StageCodes.IsValid`、`Normalize`、`Of` 和 `Resolve`。所有对外异常弹窗经 `Tools.ErrorDialog.Show(owner, fallbackStageCode, exception)`。已有阶段异常保留代码；项目、交换、导出、音频、图形、单帧渲染、图形模板、导出设置、图像序列、文本粗剪、静态帧、字幕、多机位、JSON 模型的领域异常使用显式成员映射。新增枚举成员不得改变既有代码，未知枚举成员使用该组件的 `9999`。

`MessageTipGenerator` 先遍历异常类型，再按组件选择原因和建议，不分析错误文字。无效阶段码统一为 `UNKWN0001`。对话框处理 UI 调度与已关闭的 owner；自定义对话框失败时写诊断记录并使用系统提示兜底。普通输入提示、操作确认和成功通知不属于异常诊断。

`Resources/StageList.txt` 登记组件及具体分支，并随 Debug/发布文件复制。`AUDDET`、`AUDNORM` 等旧的不合规前缀迁移为 `AUDDT`、`AUDNM`；旧的连字符诊断标签也已迁为固定格式。MCP 保留结构化 `error.code`、`message`、`stageCode`，不依赖用户点击错误弹窗继续执行。

全局异常边界为 `PROGM0001` 启动、`PROGM0010` WPF 未处理异常、`PROGM0011` 未观察的后台任务异常、`PROGM0012` AppDomain 最终异常、`PROGM0013` 诊断显示失败。WPF 未处理异常按 ZIP 的方式提示后退出，避免继续运行部分更新的界面状态。

## 防止旧对象与旧画面滞留

示例预览在选择变化时立即取消旧请求并关闭旧媒体源。每个生成请求持有自己的世代、项目、序列和取消源；UI 选择触发的请求还核对预设 ID 与分类。仅当前请求可以提交进度、播放结果或错误。新的媒体源打开前保持隐藏，`MediaOpened` 核对归属后再显示。单击、双击、拖动、失去捕获、Escape、离开窗口分别结束当前手势，不复用上一次按下的素材卡片。

时间线合成帧、图片、音频、电平、缩略图、元数据、源监视器、代理、示波器、录音等异步工作，在回写前校验所拥有的对象和来源。相同 ID 不代表相同对象；重新链接、撤销或反序列化后，还需检查引用与源路径。旧任务的 `finally` 只能释放自己的任务槽和取消源。

设置页及关键帧、效果、蒙版、转场的延迟回调，必须同时满足：当前选择仍是该对象、对象仍在当前序列、轨道未锁定、页面仍处于活动状态。焦点离开旧页不能修改后来选择的对象。

项目、序列、历史及 MCP 模型替换统一清理旧选择、手势、播放器、预览帧和异步请求。`HasActiveEditorGesture` 防止项目读写、自动保存和历史操作在拖动尚未提交时读取临时状态。后台预览片段先生成到临时目录，成功后才发布为正式缓存文件，避免取消后复用残缺视频。

MCP 示例可以不选择媒体卡片；没有原选择的被动媒体区刷新不取消它。项目或序列切换、显式重新选择、结束对应请求时仍按同一套归属规则清理。

## 导出进度窗口

普通视频导出和 MCP `export_start` 共用 `MainWindow.ExportProgress.cs` 的非模态进度窗口。准备序列、文字与图形时显示不定进度，编码时显示百分比；成功、失败或取消后自动关闭。窗口尺寸按编辑器可用大小计算，不使用固定像素尺寸。

MCP 任务在线程池执行，进度窗口必须通过编辑器 Dispatcher 创建和更新，不能在后台线程构造 WPF 控件。每个窗口绑定唯一 `jobId`；每次进度回写核对任务引用、任务 ID、所属控制会话、运行状态与窗口存活状态。终结回调只关闭该任务自己捕获的窗口，不取消其他任务，也不让已结束任务的排队进度重新显示窗口。`EXPRT0901` 标识进度窗口的创建、归属或 UI 调度边界问题。

MCP 导出窗口只读，使用 `Show()` 且不抢占焦点，不禁用主编辑器。主窗口继续遵守 MCP 输入锁定和轨道区滚轮浏览规则；进度窗口的关闭按钮不会取消导出。AI 通过 `jobs_cancel({jobId})` 取消对应任务，并等待其最终状态。普通导出仍保留窗口内取消按钮和关闭时请求取消的行为。
