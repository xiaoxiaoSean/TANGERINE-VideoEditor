# 本地语音生成

## 入口与运行方式

“工具”分类新增“语音生成”，使用原生 WPF 专用属性页。推理运行在随主程序交付的 `speech/TANGERINE-VideoEditor.Speech.exe`，采用 UTF-8 JSON 行标准输入输出协议，不启动 Node、Python、HTTP 服务或浏览器。工作进程按设备槽位复用，同一进程在模型或后端变化时释放旧会话并加载新会话；每个工作进程同时只处理一个推理请求，取消仅结束本工具创建的工作进程。

语音推理使用 Qwen3-TTS ONNX。九种预设音色来自 CustomVoice，参考录音克隆使用 Base。默认 0.6B，预设音色另提供 1.7B。推理源代码来自 MIT 许可的 ElBruno.QwenTTS 固定提交，版权与修改说明保存在工作进程 Vendor 文件夹。模型下载清单固定仓库版本、文件大小及 SHA-256 / Git blob 校验，生成本身不联网。

模型全部在根目录 `voice_models`：开发模式向上查找解决方案根目录，发行模式使用主程序目录。导入模型复制到这里；不修改运行中的既有模型目录。设备列表使用 DXGI `IDXGIFactory1::EnumAdapters1` 的索引，与当前 ONNX Runtime 1.24.2 DirectML 适配器索引一致；筛选具备 D3D12 能力的硬件，并在列表中优先排列 Intel、NVIDIA、AMD 的 PCI 厂商设备，再按专用显存排序。显示顺序变化不修改每项 `dml:索引`；自动模式选排序后第一张显卡。完整语言模型 DirectML 的容量估算仅使用专用显存，共享显存容量不代表当前可用预算；不足时使用 GPU 编码预测器与 CPU talker 的混合模式，声码器在 CPU。完整 GPU 图失败先尝试混合模式，自动模式才可继续回退 CPU；显式指定显卡不会悄悄改成 CPU。设备枚举和编译并不证明实际推理兼容性或占用率。

## 生成调度与故障隔离

独立句子可以多进程并行。worker 上限为 `clamp(ProcessorCount / 4, 1, 4)`；0.6B 自动模式最多两条 lane，1.7B 最多两个 worker。实际并发数还受当前可用物理内存约束：每份 0.6B 按 8 GiB、1.7B 按 20 GiB 预算，另预留 0.5 GiB；同模型同线程配置的已驻留 worker 不重复计入新分配预算。允许一定换页以利用本机内存，但大量换页仍可能拖慢推理。自动设备模式由一个 DirectML lane 与可容纳的 CPU lane 动态领取句子；显式指定显卡仍只使用所选显卡。同一张显卡严格使用一个工作进程和一个模型会话；CPU 池优先复用相同模型与线程配置的空闲槽。同一句的语言片段按顺序合并。设备查询使用独立进程，CPU 进程按并发数分配 ORT 线程；自动模式固定两条 lane 的线程预算，单句修改不因此重新加载会话。同一模型会话不并行调用 Run。成功后保留模型会话供增量修改复用，空闲两分钟自动回收；失败或取消只回收受影响的工作进程。内存不足时单句推理仍是顺序的，不保证 CPU/GPU 满载。

标准输入输出协议、标准错误排空和超时监控使用独立后台线程，执行中的看门狗不依赖 CLR 线程池或 UI Dispatcher。每个图加载及推理的开始、真正完成均报告 CPU/GPU 阶段；相同消息不刷新截止时间，不发送伪造的定时进度。加载最多四分钟无进展、预填充三分钟、预测和解码两分钟，超时只回收该请求的工作进程。完整 GPU 图超时先用所选 GPU 的预测器重试；混合 GPU 再次超时仅自动模式可转 CPU。按设备和模型保存混合/CPU 偏好，空闲回收后及排队任务获得槽位后仍遵守，避免每句重新探测失败路径。参考编码、文本嵌入、CPU 解码、声码器超时不误记为 GPU 故障。完成通知先更新空闲状态再发布结果，关闭实例后排队任务不能重启工作进程。音频转换另有五分钟总期限和暂存提交，失败保留原文件。所有临时结果仍在整条轨道的音频处理和排布校验成功后统一提交。

## 2026-10-26 离线性能与停滞修复

1.7B 不再在加载时串行计算三万多条投影：按实际 token 惰性缓存，矩阵向量乘法使用 SIMD。NPY 直接读入最终数组，避免约 1.2 GiB 中间副本。语音工作程序集保持 Debug 输出和符号，但开启代码优化。参考录音的 STFT 按帧并行，每个线程独立 FFT 缓冲区；幅度每个频率只计算一次。

语言模型直接保留前一轮原生 KV 输出作为下一轮输入，删除每组和每帧的大数组枚举复制，复用输入张量与 RunOptions。默认 ONNX 输出仍在 CPU，本轮没有宣称实现 GPU KV 常驻；自回归和 15 个编码组仍有数据依赖。并发、SIMD 与减少复制属于吞吐优化，不保证 CPU/GPU 仪表持续 100%。

已处理 WAV 时长只读取格式头和数据块长度；多段拼接、固定区间补齐按 PCM 块流式读写，不再把整句重复读进内存。句子后处理并行运行并报告独立进度，FFmpeg 转换使用 `-progress` 显示当前音频处理位置。声码器报告开始和完成耗时。`data/Logs/speech-worker.log` 记录工作进程每 15 秒及请求首尾的 PID、阶段、后端、累计 CPU 时间、私有内存、无进展时长；FFmpeg 转换另记录开始、完成、失败、超时及每 15 秒的进程 CPU 增量、私有内存、音频输出时间和输出文件字节数。日志不记录生成文字或参考录音。派生 DirectML 图位于 `cache/onnx-dml`，应用临时文件位于 `cache/temp`，工程语音暂存媒体位于 `cache/project-cache/.../speech`；克隆音色库位于 `data/voices`。旧 LocalAppData 仅作为工作区、导入模型登记、导出预设、音色库和模板等既有配置的一次性迁移来源。此次只执行 Debug 构建，未运行推理或测试；实际 Arc 稳定性、转换性能及末段停滞根因仍未实测确认。

进度每秒报告实际已完成图调用数、当前帧和编码组，阶段转换总是报告，汇总各 lane 当前句及已完成句数/总句数。模型可能提前输出结束标记，生成前无法准确知道总帧数，因此推理阶段进度条保持不确定状态，不用伪造的耗时估算或固定阶段权重；MCP `jobs_status` 返回 `phase`、`detail`、`completedUnits`、`totalUnits`，其中句子计数属于当前阶段，只有整条语音轨道成功提交后才达到 100%。

工作进程每 15 秒采样一次 CPU 累计时间：增量达到 0.05 秒时记录 `running-cpu-progress` 并重置无进展计时；低于该值时记录 `running-no-cpu-progress`，无进展计时继续累计。日志状态用于区分仍在同步计算与确实没有 CPU 活动的阶段，不表示 GPU 利用率，也不代表该句已经完成。

## 文字、音色与音频

2026-10-27 实例诊断：hybrid DirectML 推理约 63 秒完成，原始 WAV 有 157484 字节；紧接着转换在约 0.1 秒内因 266 字符的绝对输入路径报 `No such file or directory`。前一次只缩短输出名，仍将超长输入绝对路径传给随附的旧版 FFmpeg，因此没有解决此错误。现在转换输出始终位于 exe 同级 `cache/temp/speech-audio-<GUID>/output.wav`，过长或非 ASCII 输入先通过 .NET 复制到同一短目录；FFmpeg 读取相对短文件名，完成后再由 .NET 将输出移动到目标缓存。失败或取消后清理仅属于该转换的暂存目录；无法确认 FFmpeg 进程退出时保留暂存目录。生成失败后的工程语音目录清理发生在全部并行任务结束后，不能用失败后原路径不存在推断原始 WAV 从未生成。

模型会话固定实际恒为 1 的 `batch_size`，编码预测器固定 `num_steps=1`，不固定随文本变化的序列或 KV 长度。完整 GPU 图失败会明确提示随后是否继续 GPU 编码预测器，失败图名、异常类型和经脱敏的原生算子/形状详情写入 `speech-worker.log`。这是适配及诊断改进，旧进程中已经丢失的原始失败原因不能从后续混合 GPU 成功推断出来。Debug 内容清单排除 `dev_doc1`，开发文档仍保留在源码目录。

支持中、英、日、韩、德、法、俄、葡、西、意十种语言。自动语言交给模型处理，同一句可以人工标注多个语言片段，保持文字顺序，最后合并为一个音频对象。按句号、问号、感叹号和换行分句，小数、常见缩写不拆；生成前可手动分句和合并。

参考录音支持中文、英语提示词录制，也可导入音频/视频并选取有效范围。音色库保存标准化 24 kHz 单声道参考录音，可导出或导入 `.tvevcv`；版本清单记录音色、模型兼容、录音文字和音频校验值，不含可执行代码。没有 speech tokenizer 的 Base 模型使用说话人嵌入克隆；具备该组件时可结合录音文字进行 ICL 克隆。音色包是可复用参考音色，不冒充训练后模型权重。

音频使用实际本地推理结果，经 FFmpeg 独立处理语速（0.5～2 倍）和音调（±12 半音），并统一为 48 kHz、16 位单声道 WAV。速度不连带改变音调，音调不连带改变时长。时长读取真实 PCM 样本数，波形、监听和正式导出读取相同媒体文件。

一次性 `[s毫秒]`、`[sps百分比]…[spe百分比]` 见根目录 `voice_make.md`。句内停顿拆成同组对象并留出真实轨道空隙；速度命令处理进首次生成的基线音频，随后从保存的句子数据中消耗。之后普通文字编辑、参数编辑和单句重生成不会重新解释原始标记。

## 专用轨道与提交

轨道保存 SpeechTrackData，句子保存稳定 ID、干净文字、语言片段、可空参数覆盖、原始及处理音频媒体 ID 和位置约束。新生成独占一条音频轨道。轨道不接受外来素材，不允许普通拆分、修剪或跨轨移动；名称、锁定、静音、顺序、波形和工程混音继续使用现有功能。拖动整句设置固定起点，双端约束时平移整个区间。

位置支持自动顺排、固定起点、固定停止点和双端固定。默认从播放头开始，后续句间停顿 0.2 秒。双端根据原始音频真实时长求语速；超出范围、负起点或碰到固定句时拒绝提交。后续自动句重新排列，固定句不被移动。采样舍入只允许补短静音或移除已静音尾部，不切除有声内容。

生成在工程缓存的唯一暂存目录进行，全部生成、音频处理、约束和磁盘空间校验成功后才原子加入轨道与媒体；失败或取消删除暂存目录、保留旧轨道。音色、文字、语言、规格决定原始语音指纹；语速、音调和固定区间决定处理指纹，位置修改可复用音频。旧媒体不提前删除，保证撤销历史引用仍然有效。工程缓存释放等待语音读者，保存 .tvep 会同时打包原始与处理音频；重开后无需模型也能预览及导出。

提交检查工程对象、代次、序列、轨道内容签名、请求版本和 MCP 操作权，过期结果不覆盖新状态。GUI、MCP 共用相同服务与约束。试听复用现有请求所属音乐播放器，切换示例、音乐或时间线会撤销旧播放和封面请求。

## MCP 与检查

`speech_*` 命令覆盖设备、模型、音色、录音、分句、生成、轨道、句子参数、重排、重生成、删除和试听。长任务使用现有 jobs 查询/取消，同时显示进度窗口；遵守实例发现、锁定、实时刷新及空闲归还规则。通用轨道或片段补丁不能绕过专用语音编辑规则。详细用法见 `dev_doc2/toAI.md`。

异常使用 VOICE0001～VOICE0009，并登记 StageList。按用户要求仅静态检查与 Debug 构建，不启动软件、运行测试或生成实测音频；未把编译成功当成显卡兼容性、克隆质量或多语言发音实测。

静态复查补充：主文本修改后必须重新解析，避免生成旧分句；手动分句保留既有语言与首次速度片段。工作进程通信失败或取消后回收该进程，后续请求不能消费残留响应。模型状态查询处理异常配置，录音转换限制读取长度；推理会话选项及时释放。MCP 首次 initialRate 按字段是否提供区分“继承”与“明确 100%”，后续编辑不能重放初始速度。2026-10-23 已将三个固定版本模型下载至根目录 voice_models 并逐文件核对大小及哈希；此为资源完整性校验，不代表推理实测。

## 2026-10-24 克隆与试听修正

- 克隆录音和创建前强制选择 male/female，参考性别保存在音色清单及 .tvevcv 中。实际音色仍由用户录音的声纹决定。音色管理提供“使用所选音色”，带回生成面板，避免继续使用原预设音色。
- 参考声纹特征改用 Qwen 的 Slaney Mel 刻度；音频码重复惩罚按已出现的不同 token 各作用一次，避免长句中重复累加惩罚。ICL 同时兼容 speech_tokenizer.onnx、tokenizer12hz_encode.onnx，解码带上参考音频码上下文并按每帧 1920 采样裁去参考部分。未安装该可选编码器时显示实际声纹模式。推理指纹已升级，重新生成不会继续命中旧算法的音频缓存。
- 参考录音检查接近静音及有效声音长度；语速、音调均未变化时跳过 atempo/asetrate，避免不必要的处理。
- 音色库增加删除，创建/导入在跨进程文件锁内按 NFKC、Trim、OrdinalIgnoreCase 检查同名；音色条目在可选的导出包成功后才发布，导出失败/取消不留下占名条目。删除先移出列表再清理，只操作本地音色库，工程音频继续可用。
- 共享音频试听控制条从会被属性页隐藏的媒体列表移至预览器下方，主播放键及空格控制当前试听。音色与未生成句子支持真正的临时合成试听；参考录音有独立入口。临时资源跟随独占播放器释放，切换句子、音色或参数取消旧任务。任务等待 MediaOpened 后才报告试听成功，取消或失败保留时间线视图。MCP 增加 speech_voice_delete、speech_voice_preview，并将 gender 加入创建/录音开始契约。

以上修正只进行静态检查和 Debug 编译，没有运行测试、启动编辑器或进行实际语音听测。

## 固定克隆朗读示例

本地录音改用 SpeechCatalog 集中维护的中、英文预制文案，使用日常词汇、完整语句及自然停顿。朗读框只读且允许复制；开始录音时冻结语言及文案，保存后完整绑定参考音频，固定示例录音不提供正文裁剪。录音后切换语言清空旧参考选择并要求重录，异步保存结果按页面及请求版本过滤。MCP 的 speech_clone_prompt、speech_clone_record_start 返回相同固定文案、presetId、editable:false 及录音指引；停止录音使用开始时保存的文案快照。

导入音频也必须完整朗读当前中文或英文固定文案，不提供自定义转写。导入后可排除开头和结尾的多余部分、试听所选片段，确认其完整对应固定文案后创建；语言或有效范围变化会清除确认。MCP 创建要求从 speech_clone_prompt 获取当前 presetId，并提交 confirmedPreset:true；如提供 referenceText，必须与正文完全一致。历史 .tvevcv 仍保留实际原转写及文案版本。该文案按采集需求设计，未经过文案间的克隆质量实测对比。
