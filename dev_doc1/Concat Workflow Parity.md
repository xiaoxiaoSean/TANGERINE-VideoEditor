# Concat Workflow Parity

本次依据用户提供的 `2f_1018(1).md` 补齐剪辑功能与工作方式。对照文档作为需求参考；实现仍使用本仓库的 WPF、FFmpeg、工程模型和 MCP 管线，没有引入另一个应用或网络服务。

## 真实波形和源音轨

`MediaMetadataProbe` 读取每个音频流的音频序号、容器流号、编码、声道、采样率、语言与标题。FFprobe 的流标签通过 `stream_tags` 读取，避免旧写法只读到容器标签。元数据保存到 `MediaAsset.AudioStreams`。

`TimelineClip.SourceAudioStreamIndex` 使用音频序号，0 表示首个音频流，与 FFmpeg 的 `a:N` 一致，不能与容器流索引混用。正式导出、变速音频输入、实时监听、波形、同步、节奏分析和归一化都显式选择该流；图像代理不作为音频源。

`AudioPeakCache` 按 30 秒源窗口缓存，最多两个解码任务并行。每窗口以 48 kHz 单声道 PCM 解码，每 480 个样本取最大绝对值，保留静音、对白和拍手的位置。绘制时按当前可见像素时间范围取最大峰值，缩放不会随机变化；变速与倒放使用共同的 ClipTimeMap。解码异常记录 WAVEFORM-DECODE，不阻断编辑。

## 音频分离与归一化

分离创建引用原媒体与所选音频流的新 Audio 片段，保留入点、速度、时间映射、音量关键帧和音频处理参数。原视频通过 AudioDetached 停止发声，导出与监听统一遵守该字段，因此不会叠加两份声音。双向关联 ID 用于附着；解除链接与分离音频仍是不同操作。

附着要求音画的开始时间、时长、源入点、速度和时间重映射一致，否则显示 AUDDET0003，保留双方内容。成功时移回音频流选择、音量、静音、音量关键帧与 AudioSettings，再删除独立声音对象。上述更改均进入撤销历史。磁性模式保守保留这些分离关联对象的位置，避免自动整理破坏音画同步。

响度采用 FFmpeg R128 loudnorm 测量，不使用仓库旧简化分析器作为归一化依据。测量所选源流及片段实际区间，应用速度、声像、增益、滤波等当前处理，但关闭上一次归一化，避免重复测量累积增益。速度曲线通过真实监听窗口渲染后拼接测量。静音不能归一化，明确报错。

增益取目标 LUFS 差值与允许真峰值差值的较小值，真峰值约束优先，必要时不会强求达到目标 LUFS。测量结果、目标和增益保存为音频参数，预览与导出共用。限制器在 192 kHz 过采样域运行，关闭自动补偿；针对随附 FFmpeg 4.4 没有 latency 选项，使用 5 ms 补尾与裁切补偿前视延迟，避免音画错位。

播放电平直接读取已渲染、实际送入监听播放器的立体声 PCM 窗口。左右声道按 50 ms 计算峰值，静音与暂停显示底部电平；超过接近满刻度会保持削波标志，点击复位。这里显示 dBFS 采样电平，不冒充实时 LUFS 或独立真峰值计量器。

## 连续运动转场及边界

原实现始终复制前镜头最后一帧作为转场底图。现在对正向、反向恒速视频读取可用的后续运动余量，正式导出在同一滤镜图中把普通区间与连续尾段分开；静帧预览使用相同源时间计算。

本版本保留原来的切点和时间线长度，转场区间位于切点之后：前镜头继续读取尾部余量，后镜头从其入点继续读取。不是把两侧剪辑整体挪动、也不是改变音频时间线。

前段没有足够源余量、未知源时长、使用速度曲线或本来就是静态对象时，保留尾帧回退。转场参数页和转场右键菜单显示可用余量、需要时长和回退说明，不把定格假称为连续运动。前段倒放使用入点之前的余量；所有源时间保持非负。

## 视频防抖

使用随附 FFmpeg 的 `vidstabdetect` 与 `vidstabtransform` 两次处理，绕过旧 WarpStabilizer 中未正确解析 vidstab 输出的路径。检测强度 1–10、平滑半径 1–120 帧、边缘放大 0–50%。边缘放大为用户指定的固定上限选择，不会暗中无限放大；补偿后超出边界仍可能出现黑边，可提高放大值或使用较小平滑度。

分析所选源时间区间，生成 FFV1 无损视频、PCM 音频的 MKV 派生素材，保留全部源音轨。片段引用派生媒体且保留编辑速度、变换和效果，原媒体不改写。生成媒体加入普通媒体列表，`.tvep` 保存会把它和原素材一起打包，重开项目无须外部 `.trf`。关闭防抖恢复原媒体及源入点，可撤销。源媒体删除也考虑防抖原始源依赖。

耗时操作采用项目快照与修订检查，分析期间工程发生变化时拒绝迟到提交，不覆盖用户刚做的编辑。派生文件可能较大，这是确保可移植、无损与预览导出一致的代价。

## 磁性与快捷键

`Sequence.MagneticTimeline` 是持久工程设置。普通删除、修剪、拖动或 MCP 编辑完成时统一处理空隙，而不是只在点开关时整理一次。保留已有重叠、锁定轨道和跨轨链接/分离关联片段的位置；这些片段可用既有波纹命令显式编辑。关闭后允许保留空隙。

快捷键覆盖 16 项。单键仅在非文字输入状态执行；搜索、输入框和可编辑组合框内输入文字不会触发剪辑。自定义映射在原生 Space/J/K/L 处理前检查，保证重绑确实生效；同一手势不能分配给多个自定义命令。工作区保存、恢复与 MCP 使用同一命令列表和验证器。

## 编码与精度

正式导出按 VideoExportSettings.VideoCodec 与 BitDepth 选择 libx264、libx265 或 libaom-av1，不改变源文件。HEVC 使用 hvc1 标签，AV1 使用可用的 libaom 软件编码。AV1/HEVC 通常比 H264 更耗时。

10 位路径在图层缩放与合成前使用 gbrap16le，中间叠加为 yuv420p10，最终输出 yuv420p10le；转场亮度、闪白、光晕的采样常量随中间精度调整。不会只把最终 8 位图换成 10 位容器。专项测试用10位源视频的相邻600/601亮度值验证完整链路，最终HEVC解码后仍为600/601，保留了小于8位阶梯的亮度差。

随附 FFmpeg 的一些旧效果滤镜只能在 8 位工作。10 位导出遇到未经高精度验证的效果会给出明确错误，要求选择 8 位或关闭该效果，不会静默降低处理精度。10 位当前为 SDR 高位深输出，不宣称完整 HDR、PQ/HLG 或 HDR 元数据交付。

## MCP 和验证

新增 audio_source_streams、audio_detach、audio_attach、audio_normalize、video_stabilize、audio_meter_get 六项工具。clip_update 可切换 sourceAudioStreamIndex；sequence_update 可切换 magneticTimeline；export_start 的 settings 可选 videoCodec 和 bitDepth。工具继续遵守实例发现、先锁定、同一进程执行、实时刷新和最终释放规则。未引入 Node 或 HTTP 服务。

集中模型与 toAI.md 同步记录源流、防抖、关联字段和编码参数。项目读入与 MCP 编辑验证索引、范围及防抖配置。

`tests/ConcatWorkflowCheck` 生成两音轨测试视频，验证真实静音波形、所选流监听、分离与附着保护、R128、变速曲线、实际运动尾段、H264/HEVC/AV1 及 8/10 位文件完整解码、亮度转场、防抖两次分析、派生媒体打包重开、磁性持续生效、锁定保护、快捷键冲突和实际 MCP 调用。`McpLiveCheck` 验证真实窗口元数据、模型、工作区、管道及MCP接管；`RenderSmokeCheck` 覆盖既有效果、转场和文字渲染。
