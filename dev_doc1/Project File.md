# Project File

## 文件格式与数据关系

TANGERINE 的 `.tvep` 现在是单文件 ZIP 容器，文档格式版本为 2。`manifest.json` 储存 UTF-8 JSON 编辑指令，源媒体和代理存于 `media/<素材 ID>/`。媒体通常已经压缩，因此媒体条目以无压缩方式流式写入，清单以快速压缩写入。保存后的工程可作为单文件搬移，不依赖原媒体路径。

清单保留 `format: "TANGERINE-VideoEditor"`、`version`、序列、轨道、片段、素材箱、标记、效果和关键帧。内嵌媒体用 `tvep-media:` 引用容器条目。打开时服务在后台解出媒体到会话缓存，供预览和导出读取。项目切换后调用 `ReleaseCachedMediaAsync` 释放该工程缓存；撤销／重做替换文档对象时调用 `TransferCachedMedia` 转移缓存租约。退出时仍尽力清理遗留缓存。`JsonExtensionData` 保留未知可选字段。旧版纯 JSON 工程仍可读取，版本 1 通过显式迁移步骤升级为版本 2；相对媒体路径按旧工程目录解析，下次保存时再嵌入容器。

## 读取、保存与错误阶段

调用 `ProjectFileService.LoadAsync` 和 `SaveAsync` 读取或保存工程。服务在后台执行容器读取、媒体提取、JSON 解析、格式与版本检查和模型验证。保存先检查目标卷可用空间，再在目标目录创建临时容器，成功写入后替换目标，避免把半写入文件留作工程。手动保存和每次自动保存共用异步写入门闩，防止不同目标文件的嵌入写入并发挤占磁盘，也避免每个自动保存文件名永久占用一把锁。原媒体或代理缺失会阻止保存。取消操作传播 `OperationCanceledException`。

打开工程提取的媒体使用按工程持有的会话缓存。切换工程、撤销或重做转移缓存归属后，旧缓存异步删除；同一份缓存的重复释放会被串行化，避免清理任务与历史快照交接同时操作目录。

调用方捕获 `ProjectFileException`，通过 `StageCode` 区分路径、验证、版本、迁移、读取、解析、写入、替换及 `Space` 容量错误，并显示简体中文消息。验证覆盖序列规格和 ID、播放头及工作区范围、片段时间与画面变换、媒体入出点、素材箱父级循环、嵌套序列循环、速度节点和关键帧。容器媒体引用限定在 `media/` 下并检查条目存在且不重复。未来版本文件会在编辑前拒绝打开，保存时也会检查目标文件版本。

读取容器时限制条目总数、清单大小及每个媒体条目的实际提取字节数，并拒绝重复引用、重复条目和未引用的内容，防止损坏或恶意容器消耗无限内存、缓存空间。清单和旧版纯 JSON 使用严格 UTF-8 解码；ZIP 格式异常按读取阶段码报告。写入前也按相同条目和清单上限检查，并检查目标卷可用空间。

## 导入容量检查

导入前调用 `EnsureImportCapacityAsync(projectPath, projectedMediaPaths)`，传入现有与待导入的源媒体及代理路径完整列表；同一路径若占多个素材或代理槽位，应按实际条目重复列出。尚未命名的工程可用无 `projectPath` 重载检查临时卷；最终“另存为”还会检查用户所选目标卷。预检按媒体完整大小、每条 ZIP 索引的开销和安全余量估算，并拒绝超过条目数量上限的工程；实际写入仍处理磁盘空间在检查后变化的情况。

## 版本演进

不改变已有字段语义的功能应加入可选字段并给出默认值。若需改变已有结构或语义，应提高 `CurrentVersion`，并在 `ProjectFileService.RegisterMigration` 中逐版本注册迁移。迁移按版本顺序执行，成功后才反序列化为当前模型。工程版本与写入器不匹配时不执行覆盖保存。
