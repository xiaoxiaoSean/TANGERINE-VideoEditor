# Transition Rendering

## 目标与原有问题

原有示例使用独立 FFmpeg `xfade` 映射，在旧版编码器不支持某个名字时改成近似预设，造成名称变化但画面相同。时间线还存在“旋转开场”与整圈旋转共用公式、“轻微抖动”只是波浪形遮罩、模糊只有固定时间窗口等问题。

现在目录示例、时间线静帧和导出都使用 `TransitionRenderPlan`。转场的实现由预设 ID 选择真实的像素变换，不依赖第三方软件名称，也不通过给旧转场换名称补齐目录。

## 共用时钟与 RGBA 处理

`BuildFilters(transition, clipDuration, clock, prefix, canvasWidth)` 为每个转场生成 FFmpeg 滤镜链。导出使用片段局部 `T`，静帧预览使用实际播放位置的数值，因此动画曲线、位移、遮罩和透明度使用同一公式。

旋转、缩放、滑入、抖动、故障、胶片滚动和像素化使用 `geq` 对 RGBA 反向采样。输出画幅固定，采样越界区域透明，避免随帧改变滤镜连接尺寸或把边缘像素无限延长。旋转开场默认 90 度；旋转切换默认整圈且有缩放，两者存在实际的几何区别。

模糊滤镜实际生成高斯模糊图像，再根据动画进度与清晰图像逐帧混合。普通模糊的模糊量逐渐下降；模糊溶解的模糊量在中间达到峰值，配合不同的透明度曲线。该方案兼容 FFmpeg 4.4，避免向不支持逐帧表达式的 `gblur.sigma` 传入时间公式。模糊半径以画幅宽度比例计算，预览缩小后视觉比例一致。

## 两段片段的边界

相邻片段缺少重叠素材句柄时，保留前一片段最后一帧作为底图，新片段继续播放。转场可存储在前片段出口或后片段入口；出口转场会转换成有效的入口转场，避免只有前一帧被保留但新片段没有实际转场。有效时长同时受两段片段长度限制。

上推和下推同时移动前后两幅图像；普通左滑、右滑保留底图，只移动新画面。擦除只改变揭示区域，图像本身不移动。方向约定：向左擦除从右向左揭示，向上擦除从下向上揭示。

## 用户可调参数

`TransitionSettings.Describe(id)` 是参数唯一来源，负责字段标签、默认值、上下界和整数约束。设置界面自动显示对应字段，值写入项目的 `ClipTransition.Parameters`，保留撤销和重新预览功能。

- 所有转场：持续时间、入口或出口、动画曲线。
- 形状和擦除：边缘柔化、反向揭示；圆形、椭圆光圈、菱形支持中心位置。
- 旋转：角度，或完整圈数与顺逆时针；支持中心位置。
- 缩放：幅度和中心位置。
- 模糊：强度与高斯半径。
- 抖动、胶片、故障：位移幅度与频率；故障支持条带数量。
- 像素化：最大像素块尺寸。
- 径向扫描：中心、起始角度、顺逆时针。
- 百叶窗与棋盘：重复数量与反向。
- 斜向擦除：斜率和柔化。
- 二维折页：弯曲幅度和折边阴影宽度。
- 漏光：光效强度、暖色和光斑宽度。

原项目缺失字段时使用默认值；非有限数值和错误 JSON 数值类型使用默认值，越界参数按字段范围收敛。无效时长或未知转场类型抛出带 `ExportStageCode.Validate` 的异常，不再悄悄替换成淡化。

## 范围与验证

二维折页是带弯曲边缘和阴影的二维揭示，未实现纸张背面、厚度或真实三维卷曲。目录应使用准确名称，不宣称复刻商业软件的完整算法。相邻片段仍使用保留尾帧的策略，没有自动延长原始素材句柄。

开发验证使用应用附带的 FFmpeg 4.4，对全部 36 个预设分别取默认值、参数下界和参数上界，生成非纯色 `testsrc2` 视频：108 次图像渲染全部成功。该结果说明滤镜可执行；视觉一致性另通过实际时间线预览与导出的多帧画面检查。
