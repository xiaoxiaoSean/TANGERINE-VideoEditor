# Preview Workspace and Incremental Cache

本文记录 v1.0.0 中预览工作区与增量预览的实现。界面文案为简体中文，项目格式保持兼容。

## 视图与面板

预览器增加 10%–400% 的滑条、Ctrl＋滚轮和“回位”。100% 表示适配当前窗口。变换应用于媒体与交互覆盖层共同的父容器，鼠标坐标仍由 WPF 变换回素材坐标，文字拖动、裁切及选择框保持对应。视图缩放不写入素材 Transform，不增加工程修订或撤销步骤；示例视频进度条不参与缩放。合成帧的请求分辨率考虑显示器 DPI 和视图放大倍数。

上方媒体区和预览区增加左右分隔条，上方工作区与时间线之间的分隔条改为比例高度。面板最小范围为可用宽度或高度的 15%。加载布局时统一为总计 100 的星号权重，避免原先 0.44 / 0.56 与新增 1* 分隔条组合后把一半空间留给分隔条。

媒体区提供列表、小缩略图、大缩略图。缩略图只对可见卡片请求；时间线只对可见片段区域请求。图片和视频共用解码缓存，视频按源时间每半秒分桶，因此裁剪、速度及反向映射后的时间线样本仍对应实际素材。最多两个 FFmpeg 解码任务并行，相同请求合并，已完成项按容量淘汰。缺失媒体通过 THUMBNAIL-LIBRARY / THUMBNAIL-TIMELINE 诊断记录，不阻断编辑。

在轨道真正的空白画布按住左键并上下拖动可改变轨道层级，使用既有的悬浮预示、自动滚动和撤销机制。Shift 保留框选；播放头、关键帧、曲线和片段控制点保留原来的交互。没有发生拖动时，单击空白处仍可定位播放头。分割按钮一次单击立即执行；未预选片段时，先解析播放头下、当前轨道优先的未锁定片段。

滤镜和特效归入统一的“效果”，预设 ID、参数和已有项目均保持兼容。

## 图片叠加清晰度

原合成路径先把每个输入降到预览窗口分辨率，再应用素材放大变换；被丢弃的细节在后续放大时无法恢复。现在先按序列分辨率合成，再用 Lanczos 缩小至实际预览尺寸，WPF 也使用高质量位图缩放。显示器像素与放大倍数参与请求尺寸。复杂合成的计算量会随序列分辨率提高，连续播放优先使用下述后台缓存。

## 整个工程的后台缓存

停止输入约两秒且没有播放、导出或 MCP 任务时启动。一次最多一个后台工程缓存任务。后台使用独立项目快照，沿用正式导出的文字、效果、转场和编码管线；优先探测并使用可用 GPU 编码，硬件编码失败时回退软件编码。CPU 软件渲染偏好会禁用该 GPU 编码选择。

工程按约三秒、整数帧对齐的时间段划分。每段指纹包含序列画幅、色彩、帧率、相交片段及参数、图层顺序、源文件/代理标识与时间戳、效果外部文件依赖等。边界转场的上一片段也纳入依赖；嵌套序列和多机位依赖保守处理。播放头、工程修订号、界面选择和工作区比例不进入内容指纹。

编辑立即取消正在进行的推测渲染并废弃旧播放清单。再次空闲时重新计算指纹：命中磁盘的段直接复用，仅缺失段重新编码。全部段完成后通过 concat 与视频流复制拼接，清单为每段明确指定帧时长，避免 AAC 容器尾部时长使接缝逐段漂移。拼接结果原子发布，并核对工程世代与修订，取消或迟到任务不能覆盖当前工程。

正向播放使用已完成的整段缓存视频；暂停、倒放、拖动播放头或编辑时回到交互帧预览。声音继续使用现有时间线音频监视器，保留实时静音/独听。缓存不是正式交付文件，正式导出始终读取原项目数据。

缓存位于 `%LOCALAPPDATA%\TANGERINE-VideoEditor\cache\timeline-v2`。完成后清理超过七天或历史累计超过约 2 GB 的非当前缓存；当前工程需要的段不在清理范围内。失败显示 PREVIEW-CACHE-RENDER / PREVIEW-CACHE-PLAY，恢复原预览能力，不影响保存与正式导出。

## MCP 与文档

已有 workspace_get / workspace_set 增加 previewViewZoom（0.1–4）与 mediaViewIndex（0 列表、1 小图、2 大图），状态同时可以保存、恢复、重置。AutomationCatalog、实际界面及 toAI.md 的参数定义一起更新。

toAI.md 的首节明确：日常剪辑使用客户端已经连接的 MCP 工具，不编写 Node / Python 桥接、不搭建服务器、不模拟协议。没有连接时指导配置随应用提供的 .NET MCP 可执行文件。

## 验证

`dotnet run --project tests/PreviewExperienceCheck -c Debug` 验证分隔条实际布局、缩放不改工程、视图切换、图片/视频源时间缩略图、高频图片合成、分段失效、真实缓存渲染、拼接解码、帧数与时长、未改动段复用、取消和单击分割。测试自行发现默认 Debug 的 FFmpeg；需先编译主程序。

既有 McpLiveCheck、McpControlCheck、TrackRenameCheck 验证新参数、实时界面、独占控制及滚轮浏览；RenderSmokeCheck 覆盖既有效果与转场合成管线。


## 素材拖动与单击示例回归修复

素材拖动改为在按下时按实际鼠标命中绑定 LibraryItem，移动阶段只使用该对象，禁止从上一轮 SelectedItem 推断拖动数据。鼠标按下由素材区持有手势，避免 ListBoxItem 默认捕获把后续事件路由到旧卡片。原生 DoDragDrop 放在 try/finally 内，成功、取消、Escape、拖回或在窗口外松开都会清空按下对象与拖动标记、删除轨道幽灵；DragLeave 与素材区 DragOver 同时清理幽灵。拖回素材区放下内置对象明确返回 None，不添加轨道片段。时间线重绘后再次 DragOver 可重新挂接当前幽灵。

示例预览只在一次完整单击松开后启动，选择变化不再启动第二个任务。相同卡片再次点击仍可重新播放，双击保留添加素材行为。示例生成中与播放中均独占预览画面，先取消旧时间线合成和图片读取；时间线 Seek、覆盖层、尺寸变化的合成请求，以及迟到合成结果均不能覆盖示例。世代与取消令牌保证快速切换只接收最后一次请求。

`tests/LibraryInteractionCheck` 在真实 WPF 窗口内用实际卡片坐标、真实示例编码、DragLeave 路由及 Drop 数据验证连续选不同对象、拖回取消、幽灵清理、单击/重复点击/快速切换、异步合成隔离与最终落下对象的预设。
